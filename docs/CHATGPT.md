# Connect MCP clients and ChatGPT

## Verify locally first

Run `run_bridge.py doctor` using the Python executable in `.venv`. For a local MCP
client, configure the absolute path to `.venv/bin/python` and the absolute script
path `run_bridge.py`, followed by `stdio`. The client's working directory can be
anywhere. This entry point does not open a public HTTP port.

For Blender, use `.venv-blender/bin/python` with `ops/blender_entry.py`. For Unity,
use the client configuration generated by the project's plugin. These are three
independent MCP servers.

Example for clients that accept `mcpServers` (replace the paths):

```json
{
  "mcpServers": {
    "pcbridge-linux": {
      "command": "/absolute/PCBridgeLinux/.venv/bin/python",
      "args": ["/absolute/PCBridgeLinux/run_bridge.py", "stdio"]
    },
    "blender-linux": {
      "command": "/absolute/PCBridgeLinux/.venv-blender/bin/python",
      "args": ["/absolute/PCBridgeLinux/ops/blender_entry.py"]
    }
  }
}
```

The installer generates an example with actual paths in `.local/mcp-client.json`.
Adapt the fields if your client uses a different schema. Include Blender only after
installing its environment with `--with-blender`.

## ChatGPT account setup

Official references were checked on 2026-09-08. Availability depends on your account.

Follow the [official connection guide](https://developers.openai.com/plugins/deploy/connect-chatgpt):
enable Developer mode under Settings > Security and login if your account permits
it. Create a connection in Plugins and choose Tunnel. Review the tools and start a
conversation with the connection enabled. Use Refresh after tool metadata changes.

[Secure MCP Tunnel](https://developers.openai.com/api/docs/guides/secure-mcp-tunnels)
requires a tunnel, runtime key, and the appropriate organization/workspace association.
Each user supplies their own; this repository contains no shared account credentials.
Download the Linux client through the official guide and run `tunnel-client help quickstart`.

After configuring authentication as described in that guide:

```sh
tunnel-client init --sample sample_mcp_stdio_local --profile pcbridge-linux --tunnel-id YOUR_TUNNEL_ID --mcp-command '/absolute/PCBridgeLinux/.venv/bin/python /absolute/PCBridgeLinux/run_bridge.py stdio'
tunnel-client doctor --profile pcbridge-linux --explain
tunnel-client run --profile pcbridge-linux
```

If installation paths contain spaces, quote each path inside the `--mcp-command`
value according to the installed client's syntax. For Blender, configure a separate
stdio profile. For Unity, use `--mcp-server-url` with the editor's local MCP endpoint.
Keep each tunnel client running. A private tunnel is separate from public plugin publication.

## Avoid conflicts

Choose new profile names. When running multiple tunnel clients, assign distinct
diagnostic ports in their generated configurations, following the installed client's
help. Do not reuse another installation's profiles, IDs, admin ports, or services.

Keep keys outside Git and the authorized workspace. Do not put credentials in
command arguments or documentation. If you configure automatic startup, start the
tunnel process rather than an isolated stdio server: stdio needs a client reading
and writing its streams. Use a user systemd unit pointing to the new configuration.
This is a manual step and requires testing after login.

## End-to-end checks

1. Bridge: list the workspace and read a test file; reading outside it must fail.
2. Unity: identify the project, open scenes, and editor state; inspect Console and Game View.
3. Blender: identify the scene, objects, and file; capture the viewport.
4. Test desktop capture and a reversible change in a disposable folder or scene.
5. Restart only the new connection and verify that the editors remain open.

An online tunnel or open port alone does not demonstrate a working editor integration.
